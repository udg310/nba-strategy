## 1. 规则

`m_fav` = 强队得分 − 弱队得分；主客只旋转符号。

| | A 弱队领先 | C 比分接近弱队起势 | D 末节强队锁胜 |
|---|---|---|---|
| 赛前过滤 | 强队 ≥0.60 | 无 | 强队 ≥0.60 |
| 状态 | `m_fav ≤ −5` | `−5 ≤ m_fav < 0` | Q3 剩 6:00 起，`5 ≤ m_fav < 10` |
| 信号 | 120 秒比赛时钟内 `m_fav` 再降 ≥3 | 同左 | 首个状态时点 |
| 买入 | 弱队 | 弱队 | 强队 |
| 入场 | ≥0.10，无上限 | 同左 | 全成本 0.70–0.80，不合格放弃 |
| 出场 | TP+20c / Q4 6:00 强平 | TP+20c / **30 分钟比赛时钟**市价卖 / Q4 6:00 强平 | 结算；**`m_fav < 0` 后市价卖（margin_stop）** |
| 仓位 | 1.0× | 1.0× | 2.0× |

成本：实盘实测往返约 `0.10·p·(1−p)`，外加一档价差；代码按每边
`0.005 + 0.05·p·(1−p)` 计。

## 6. 执行层修复（已在 `live_runner.py`）

1. **重复下单**：一个信号只发一次单；用 `get_trades` 的订单/成交 ID 确认，
   不用滞后的 token 余额；发出后未确认绝不重发。
2. **卖出记账**：每个仓位只卖自己的股数；成交记录确认；<0.02 股粉尘直接
   关闭，不再空转 15 分钟。
3. **A/C 共享 token**：不再互相整仓卖出。
4. **400 invalid amounts**：买入市价单强制 tick 0.01（0.001 tick 会要求
   5 位小数，被服务器拒绝）。
5. **入场价**：使用成交记录的加权均价，不用 ask。
6. **重启恢复**：按 买入−已卖 重建；共享 token 按记录股数分配；保留原始
   入场时间和比赛时钟入场点，C 的时间退出不会因重启重新计时。

## 7. 分比赛交易员架构

- 主线程每 3 秒轮询 ESPN，解析市场，开赛时为每场比赛启动一个
  `GameTrader` 线程；比赛结束且无仓位后释放。
- 每个 trader 拥有自己的 CLOB client、比分历史、信号状态、挂单、持仓和
  出场检查；单个 trader 崩溃记为 `game_err`，不影响其他比赛。
- 每个 tick 并行检查各自持仓的出场；`ALL_POSITIONS`、`MAX_OPEN`、
  已确认买卖标志在锁下共享。
